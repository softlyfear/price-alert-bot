# price-alert-bot

Telegram-бот, который следит за ценами на **Wildberries** и **Ozon** и сообщает, когда товар подешевел или подорожал до нужной вам цены.

## Возможности

- Добавление товара по ссылке, короткой ссылке Ozon «Поделиться» или артикулу.
- Порог в рублях. Направление выбирается само: ниже текущей цены — «сообщить, когда дешевле», выше — «когда дороже».
- Проверка цен по расписанию (по умолчанию раз в 15 минут), повторное уведомление не чаще раза в сутки.
- До 50 товаров на пользователя, постраничный список «Мои товары».
- Цена без персональных скидок маркетплейса (кошелёк, карта, баллы): на сайте она может быть ниже.

| Команда | Что делает |
|---|---|
| `/start` | приветствие и список команд |
| `/help` | подробнее о боте |
| `/add` | добавить товар в отслеживание |
| `/list` | мои товары и пороги |
| `/cancel` | отменить текущее действие |

## Стек

Python 3.14 · aiogram 3 · FastAPI · SQLite · SQLAlchemy 2 · Alembic · Redis · Playwright (Chromium) · curl_cffi · Docker

## Установка на сервер

Нужны Docker с плагином `compose`, `git` и `make`.

```bash
git clone https://github.com/softlyfear/price-alert-bot.git
cd price-alert-bot
cp .env.example .env
nano .env            # заполнить переменные, см. ниже
make docker-up       # сборка образа, миграции, запуск
```

Минимум, который нужно заполнить в `.env`:

| Переменная | Что это |
|---|---|
| `TG__BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `DB__ECHO` | `False` на сервере |
| `OZON__PROXY_URL` | необязательно: SOCKS5-прокси для Ozon, `socks5h://<логин>:<пароль>@<хост>:<порт>` |

Остальные переменные можно оставить как в `.env.example`. Compose задаёт путь SQLite в постоянном томе и адрес Redis. База должна находиться на локальном диске, бот запускается в одном экземпляре на одном сервере.

> Один токен — один запущенный бот. Если бот уже работает на другой машине, сначала остановите его там, иначе Telegram вернёт `TelegramConflictError`.

## Управление

| Команда | Что делает |
|---|---|
| `make docker-up` | собрать, применить миграции и запустить (и для обновления после `git pull`) |
| `make docker-logs` | журнал |
| `make docker-restart` | перезапуск |
| `make docker-down` | остановить стек (данные в томах сохраняются) |

Все сервисы стека под профилем compose `price-alert-bot`: обычные `docker compose up/down/restart` без `--profile price-alert-bot` его не трогают.

## Резервное копирование SQLite

На работающем стеке создайте новую копию в доступном локальном каталоге:

```bash
make db-backup BACKUP=/путь/к/новой-копии.sqlite3
```

Копия создаётся через SQLite Online Backup API и проверяется; существующий файл не перезаписывается. Храните её отдельно от сервера и периодически проверяйте восстановление.

Для восстановления остановите бота, затем укажите файл копии. Пока идёт восстановление, не запускайте приложение, миграции и другие процессы с доступом к тому:

```bash
docker compose --env-file .env --profile price-alert-bot stop app
make db-restore BACKUP=/путь/к/копии.sqlite3 OVERWRITE=1
make docker-up
```

`OVERWRITE=1` разрешает замену существующей базы. Без него восстановление возможно только в отсутствие файла назначения. Копия проверяется до замены; её схема должна соответствовать текущей версии приложения. Для старой копии сначала верните соответствующую версию приложения, восстановите копию и затем обновите приложение с миграциями. При файлах `-wal`, `-shm` или `-journal` рядом с копией или базой в томе восстановление откажет. Закройте процессы, использующие копию; состояние тома с такими файлами сначала сохраните и разберите отдельно. При другом `ENV_FILE` используйте его во всех командах.

## Переход с PostgreSQL

Перед будущим обновлением сервера сохраните проверенную резервную копию PostgreSQL, текущую версию кода и `.env`. На **старой версии**, до `git pull`, остановите старый стек командой `make docker-down`: тома останутся на месте. Затем обновите код, проверьте новый `.env` по `.env.example` и запустите `make docker-up`. Создастся пустая SQLite-база: старые пользователи, товары и алерты автоматически не переносятся. Старый том PostgreSQL не удаляйте.

Для возврата остановите новый стек, верните сохранённую старую версию кода и `.env`, затем запустите старый стек с прежним томом PostgreSQL. При необходимости восстановите PostgreSQL из сохранённой копии по её инструкции.

## Разработка

Нужны Python 3.14, [`uv`](https://docs.astral.sh/uv/) и запущенный Redis, адрес которого указан в `.env`. Для пустой локальной SQLite сначала создайте каталог `data`; миграции создадут файл базы.

```bash
make install           # зависимости
mkdir -m 700 -p data   # каталог локальной SQLite
make install-browser   # Chromium для Playwright
make hooks             # git-хуки
make run               # миграции и сервер с автоперезагрузкой
```

Проверки перед коммитом:

```bash
uv run ruff check . && uv run ruff format --check .
uv run mypy app tests
uv run lint-imports
uv run pytest --cov=app
```

Остальные цели — `make help`.
